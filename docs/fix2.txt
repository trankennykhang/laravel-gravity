# ==============================================================================
# Root Causes and Fixes Applied
# ==============================================================================

1. OpenTelemetry PHP Packages Missing from vendor/ & composer.lock Mismatch:
   - Root Cause:
     composer.json contained OpenTelemetry packages (and unused packages like wordpress,
     slim, and zipkin), but composer.lock had not been updated and composer install/update
     had never been executed. The vendor/open-telemetry directory did not exist.
   - Fix:
     - Cleaned up composer.json by removing unused instrumentation packages.
     - Executed "docker compose exec app composer update" inside the container.
     - Verified OpenTelemetry SDK classes (TracerProvider, MeterProvider, LoggerProvider)
       loaded and initialized properly.

2. CLI Tracing Disabled by Default in OpenTelemetry PHP:
   - Root Cause:
     When running Artisan CLI commands, OpenTelemetry PHP disables tracing by default
     in CLI SAPI (returning a NoopTracer with Trace ID "00000000000000000000000000000000")
     unless OTEL_PHP_TRACE_CLI_ENABLED=true is set.
   - Fix:
     - Added "OTEL_PHP_TRACE_CLI_ENABLED=true" to environment variables for both "app"
       and "queue" services in docker-compose.yaml.
     - Artisan commands now generate active traces with real Trace IDs recorded in Tempo.

3. Grafana Datasource UID Inconsistency & Broken Trace-to-Logs:
   - Root Cause:
     Grafana auto-generated random alphanumeric UIDs for provisioned datasources (e.g.,
     P8E80F9AEF21F6940) because explicit "uid:" fields were missing in datasources.yaml.
     The Tempo datasource referenced "datasourceUid: 'loki'", which failed to resolve.
   - Fix:
     - Updated docker/observability/grafana/provisioning/datasources/datasources.yaml:
       - Added deleteDatasources to purge stale auto-generated UIDs.
       - Defined fixed UIDs: "prometheus", "loki", and "tempo".
       - Configured tracesToLogsV2 with tag mapping for service.name.

4. Absence of Pre-configured Dashboards in Grafana:
   - Root Cause:
     Grafana had datasources provisioned but zero provisioned dashboards. Users landing
     on Grafana at http://localhost:3001 had an empty homepage and had to manually construct
     queries.
   - Fix:
     - Added dashboard provisioning volume mounts to docker-compose.yaml.
     - Created docker/observability/grafana/provisioning/dashboards/dashboards.yaml.
     - Created docker/observability/grafana/dashboards/laravel-observability.json with:
       - Stat panels for OTel Collector scrape status and test hit counters.
       - Time-series panel for Prometheus scrape duration.
       - Live log stream panel querying Loki for {service_name=~".+"}.
       - Quick reference markdown links for Grafana Explore.

5. Telemetry Buffering / Delayed Flush in PHP Scripts:
   - Root Cause:
     OpenTelemetry exporters buffer telemetry batches. Without an explicit forceFlush(),
     short-lived CLI commands or fast web requests could terminate before the batch was sent.
   - Fix:
     - Added forceFlush() calls on TracerProvider, MeterProvider, and LoggerProvider in both
       the Artisan command and the web test route before response return / command exit.

6. Grafana Port Inconsistency in Documentation:
   - Root Cause:
     docker/observability/README.md stated Grafana was exposed on port 3000, but
     docker-compose.yaml mapped port 3001:3000 to prevent local port conflicts.
   - Fix:
     - Updated docker/observability/README.md to reflect port 3001 and included full
       testing and exploration instructions.


# ==============================================================================
# Quick Reference Guide: Testing & Viewing Data
# ==============================================================================

1. Trigger Telemetry via Artisan:
   docker compose exec app php artisan telemetry:test

2. Trigger Telemetry via Web:
   curl http://localhost:8080/otel-test
   (or open http://localhost:8080/otel-test in a web browser)

3. Automatic Tracing:
   Browse any standard Laravel route (e.g. http://localhost:8080/ or http://localhost:8080/login).
   Traces are automatically captured and routed to Tempo.

4. Grafana URLs (Port 3001, Anonymous Admin enabled):
   - Overview Dashboard: http://localhost:3001/d/laravel-gravity-overview
   - Explore Tempo:      http://localhost:3001/explore (Select "Tempo" datasource)
   - Explore Loki:       http://localhost:3001/explore (Select "Loki", query: {service_name=~".+"})
   - Explore Prometheus: http://localhost:3001/explore (Select "Prometheus", query: test_counter_count_total)
