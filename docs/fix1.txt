# ==============================================================================
# Root Causes and Fixes Applied
# ==============================================================================

1. Queue Container (laravel-gravity-queue) & App Container (laravel-gravity-app):
   - Root Cause:
     Dependencies in vendor/ (installed via composer, including symfony/* v8 components)
     required PHP >= 8.4.0. The Dockerfile was using "FROM php:8.3-fpm". When the queue worker
     started, vendor/composer/platform_check.php threw a fatal RuntimeException:
     "Your Composer dependencies require a PHP version '>= 8.4.0'. You are running 8.3.33."
   - Fix:
     - In docker/Dockerfile: Updated line 1 to "FROM php:8.4-fpm".
     - Rebuilt images with "docker compose build app queue" and recreated containers with
       "docker compose up -d app queue".

2. Tempo Container (laravel-gravity-tempo):
   - Root Cause:
     a) Tempo v3 (grafana/tempo:latest) removed the top-level "compactor:" configuration
        block, resulting in:
        "failed to parse configFile /etc/tempo.yaml: line 11: field compactor not found in type app.Config".
     b) In docker/observability/tempo.yaml, distributor receiver protocols did not specify
        an IP address, defaulting to 127.0.0.1 and rejecting connections over the docker network.
     c) The named volume "gravity-tempo-data" was initialized with root:root permissions (755).
        Since Tempo runs as UID 10001:10001, it failed to write with:
        "mkdir /tmp/tempo/blocks: permission denied".
   - Fix:
     - In docker/observability/tempo.yaml:
       - Removed the obsolete "compactor:" section.
       - Explicitly bound distributor receiver endpoints to 0.0.0.0:4318 (HTTP) and 0.0.0.0:4317 (gRPC).
       - Added "wal: path: /tmp/tempo/wal" under storage.trace.
     - Changed ownership of the volume directory to UID 10001:10001:
       docker run --rm -v laravel-gravity_gravity-tempo-data:/tmp/tempo busybox chown -R 10001:10001 /tmp/tempo
     - Restarted Tempo: "docker compose restart tempo".

3. OpenTelemetry Collector (laravel-gravity-otel):
   - Root Cause:
     Recent releases of otel/opentelemetry-collector-contrib removed the legacy "loki" exporter,
     failing startup with:
     "'exporters' unknown type: 'loki' for id: 'loki'".
   - Fix:
     - In docker/observability/otel-collector-config.yaml:
       - Replaced the "loki" exporter with "otlp_http/loki" targeting Loki's native OTLP endpoint:
         endpoint: "http://loki:3100/otlp"
       - Updated the logs pipeline exporter to use "otlp_http/loki".
       - Modernized "otlp/tempo" exporter to "otlp_grpc/tempo" to eliminate deprecation warnings.
     - Restarted collector: "docker compose restart otel-collector".
